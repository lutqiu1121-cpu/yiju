## 一键启动 · 启动项

解压源码包，进目录直接：

```bash
./start.sh                 # Linux / macOS；Windows 用 start.bat
./start.sh --port 9000     # 临时改端口，不改配置
./start.sh --no-directory  # 临时关外部名录
./start.sh --help          # 打印全部启动项
```

`yiju.conf`（首次运行自动生成，改完保存即生效）：

| 项 | 默认 | 说明 |
|---|---|---|
| `HOST` | `0.0.0.0` | 监听主机 |
| `PORT` | `5080` | 任意 1–65535 端口 |
| `HALL` | 弈局棋馆 | 本馆匾额 |
| `DIRECTORY` / `TIME` / `BOARDS` | `on` | 名录 / 校时 / 榜单，均可关 |
| `ROOT` | `.` | 项目根（`client/` `rules/` `scripts/` `data/` 所在） |
| `OPEN` / `BUILD` | `no` | 启动后开谱页 / 启动前先构建 |

命令行启动项：`--url / -u`、`--port / -p`、`--host`、`--hall / --name`、`--root / --data`、`--directory on|off`、`--no-directory`、`--time on|off`、`--no-time`、`--boards on|off`、`--no-boards`、`--open`、`--build`、`--config`、`--help`、`--version`。环境变量：`QIPAI_URL` `QIPAI_PORT` `QIPAI_HALL` `QIPAI_ROOT` `YIJU_CONF`。优先级 **命令行 > 环境变量 > yiju.conf > 默认值**。

服务端另给 `/api/health`、`/api/info`、`/api/startup` 三个只读端点；`/ws` 为对局长连接。启动日志会做「布局自检」，缺 `client/` `rules/` `scripts/` 会直接报出来。


## 快速开始

**房主（起棋馆的人）**

```bash
dotnet run --project server
# 或构建后： dotnet publish/server/qipai-server.dll
```

  一键启动：解压源码包后执行 `./start.sh`（Windows：`start.bat`）。它会读同目录 `yiju.conf`，自动建 `data/` `scripts/`，检查 dotnet，然后起棋馆并打印可照抄地址。改端口 / 匾额 / 开关只改这一个文件；命令行参数可临时覆盖。启动项全表见下节。
  房主本机浏览器打开 `http://localhost:5080`（这是本机访问地址，**不是玩家必须填的地址**）。启动日志会打印局域网地址、棋馆名与剧本数。

**玩家（只装 APK）**

  同 WiFi 下打开 APK → 首启「选一个棋馆」点一下，或到「肆 · 案牍」填**任意可达地址** → 状态灯变「已联机」即可开局。局域网 IP、域名、IPv6、带路径地址、本机回环都认，不绑定任何固定地址；端口写不写都行，不写自动补「缺省端口」（默认 5080，设置里可改）。**账号可选**：不必题名照样玩（战绩记本机榜）；想带走战绩就题名，之后每局自动写进加密存档。**没有中央账号棋馆**。

> 一台房主棋馆就是一个独立棋馆：自带自己的剧本、本机榜、房间与隐士陪玩。谁都能开自己的馆，互不依赖。

## 入门教程（第一次用，约 2 分钟）

同样的内容也做在 App 里：今日页「初来？且看一遍小引」，首次打开自动弹一次；「肆 · 案牍 → 入门小引」可随时重看。

  **壹 · 连上棋馆** — 房主 `./start.sh` 一键启动（或 `dotnet run --project server`），启动日志会打印可照抄的地址。玩家与主机同一 WiFi，APK 首启「选一个棋馆」点一下即可，或到「肆 · 案牍 → 棋馆地址」手填任意可达地址。棋馆目录默认开启，挂了也不影响手填。

**贰 · 设席开枰** — 建房可题雅号、设暗语、许旁观、定每步思考 / 出牌之刻与超时之法、挑十阶隐士棋力；每局还有本局专属规制，都在「房规」里。记下五位房号，另一台设备填之点「赴局」。人未齐可一键请隐士补满，快速匹配等 8 秒也自动补齐；真人入席，隐士自退。

**叁 · 落子与出牌** — 棋盘小圆点是可落处；走子类先点己子再点目标格，牌类先选手牌再「出牌」。房内可打字闲谈、发一键短句，还看得见谁正在打字。折狱录跟幕卡走：旁白逐句、线索翻牌、轮流打字发言、终幕指认，私本只自己可见。弈卷两席同时覆简、启简后界墨推移，弃简区可推对方余牌；七局原创小戏也是「各覆一手、同时启看」，点卷面上的笺格即可。

**肆 · 横竖屏与外观** — 竖屏盘在上、牌在下、底部「〇—肆」导航；横屏左盘右信息栏，导航收成侧边细条。10 套纸色可换，剧本开局自动切它指定的颜色，散场恢复你选的；落子发牌有轻动画，系统开了「减动效」会自动收敛。

**伍 · 存档 / 段位 / 弈株 / 剧本 / 源码** — **账号可选**，不题名照样玩（战绩记本机榜）；题名后自动建一份加密存档，每局终了自动写回，可导出 `.yijusave` 携往别的棋馆，导入须再验口令。段位七阶按赛季重置，馆赛所得折半计入、自修全额，隐士十阶随段位增强。**神的领域**：六十局各自独立，此局段位先至顶阶「弈圣」方可叩域；三尊依次 **青冥 → 玄枢 → 太虚**，胜首尊即得神衔 **弈神**，再胜逐字加前缀为 **玄弈神**、**太玄弈神**，得衔不回退。三尊隐士读完整局态（对手手牌、暗子、未发之牌皆在眼底）、多层深搜与终局推演逐档加深，逐尊收更漏；挑战局禁悔、禁和、不计段位。全 60 局共用一套界面特效（落子涟漪、萤火、朱印、幕间绫带、终局星雨），并尊重减动效偏好；四件华彩可用弈株购得（流萤 / 描金 / 朱澜 / 星雨）。对局终了另赠**弈株**（胜十二 / 和六 / 负三，每日至多六十枚）：只换牌桌、牌面、朱印、墨色等外观，不入局内、不改胜负、不兑换、无充值；「肆 · 案牍 → 弈株 · 装扮」可购可配戴。剧本另可在「制本」里可视化编写人物 / 线索 / 幕 / 结局，验本后下载成 JSON 或当场呈本。「叁 · 战绩」有本机榜与棋馆目录。剧本只放房主本地 `scripts/`，丢一个新 JSON 即更新，亦可当场呈本；断线重连自动续局，终局可回放，「肆 · 案牍」可导入导出棋谱。源码与「源码公开 · 禁止商用」协议随版本发布。

## 赛季 · 天时 · 段位

- **赛季历（东八区）**：第一赛季 2026-11-22 — 2026-12-31；第二赛季自 2027-01-01 起，其后每 30 个自然日一季，连续不中断，不按自然月。
- **谁联网**：**手机端**联网取两处以上独立天时凭据，通过 WebSocket 交给房主棋馆；**棋馆服务端自身不联网**，只验凭据并用同一份历法重算赛季，不采信手机端报来的赛季编号。
- **防篡改**：段位与积分只落在棋馆本地的加密存档里，手机端本地存储不再是权威；导入 `.yijusave` 会剔除赛季与段位字段，由接收端按当前权威赛季重建；改本机时间、改本地存档都改不了赛季与段位。
- **换季**（参考通行做法）：归档上季最高段位、发一枚赛季印记、各局积分清零、按上季段位承袭一部分墨分作为新季底分（弈圣→国手起点，依次递减）。
- **纯局域网**：无外网时自动降级为「未校天时 · 依本席更漏」，赛季照算、段位照记、承袭照做，界面只多一枚状态标记；联网恢复后自动重校并广播全馆。局域网联机与能联网的棋馆体验一致。
- **重校**：「肆 · 案牍 → 天时 · 赛季」可随时重校，也可自填一个校时帖地址；默认公共天时源可换、可关，不绑定任何一家。

## 折狱录：房主本地读本，棋馆转发

**剧本不在 APK 里、不在浏览器里、不在中央棋馆上。** 它只在房主棋馆 `scripts/` 目录：

```
房主 scripts/*.json  →  房主选本  →  他的棋馆读盘
                                  ↓ WebSocket
                          按座位投影发给所有客户端
                          （每人只拿到自己的私本）
```

- 别人不用装、不用更新、不用账号；连进来就收到演出内容
- 剧本清单走 WS（`t:scripts`），不走 HTTP —— APK 是 `file://`，本来也访问不到 `/api`
- **更新 = 往 `scripts/` 丢新 JSON，或把 `version` +1**。开新房时棋馆重读，不用重启、不用发版
- **现场呈本**：房主在「肆 · 案牍 → 呈本」粘贴 JSON 或选文件，只作用于本席、不落盘、别席不见
- **剧本编辑**：同页「制本」可视化增删人物 / 线索 / 幕 / 结局，客户端先验本（线索引用、角色编号、结局），再下载放进 `scripts/` 长期用或当场呈本；草稿存本机
- 仓库带 3 个完整示例本：雨夜旧宅(悬疑还原)、灯下无信(情感)、末班电车(奇幻)，含角色私设、公/私线索、三幕、结局分支与氛围配置

### 剧本格式（可直接照抄改）

```json
{
  "id": "yuye-jiuzhai", "name": "雨夜旧宅", "version": 1,
  "min": 4, "max": 7, "minutes": 45, "theme": "夜墨",
  "synopsis": "一封十年前的邀请函，把几个人叫回空了很久的宅子。",
  "roles": [{ "id":"guanjia", "public":"管家",
    "private":"你知道书房的锁三个月前换过。", "secret":"信其实是你寄的。",
    "goal":"终幕前别被指认出来。", "botLines":["雨太大了，各位先别上楼。"] }],
  "acts": [{ "no":1, "title":"第一幕 · 门铃",
    "narration":["雨从傍晚就没停过。","谁也没先开口。"],
    "revealDelay": 900, "publicClues":["c1"],
    "privateClues": {"guanjia":["c2"]}, "discussMs":240000, "cue":"doorbell" }],
  "clues": { "c1": {"title":"门厅的伞","text":"六把伞，其中一把是干的。"} },
  "endings": [{ "when":"vote","title":"真相","text":"……" }],
  "ambience": {"drone":"rain","ink":0.7,"paper":0.5,"cueVolume":0.6}
}
```

坏本（缺 `roles` / `acts`）自动跳过，不影响其他本。

### 怎么演出

**棋馆当导演，客户端只当舞台**，阶段绝不交给客户端推进：

`幕卡 → 旁白逐句浮现 → 线索翻牌(公栏/私窗) → 轮流打字讨论 → 指认 → 结局黑卡`

- 幕间：全屏 `ACT Ⅱ` 衬线大字 + 墨晕淡入 + 一记合成磬声
- 旁白按 `revealDelay` 分句浮出，不能快进；读完才发线索
- 线索卡手绘不规则描边、点一下翻面；私秘线索带朱砂封蜡角标，单独小窗
- 讨论按座位轮流打字（全房可见），一轮说完自动进下一幕；读秒超时由棋馆托管代说一句，不会冷场
- 指认复用投票面板，棋馆收齐最后一张票才结算
- 结局黑卡白细线，按 `endings` 分支出文本

**氛围零资源**：雨声/静室/电流用 WebAudio 实时合成（noise + lowpass + 低频 drone），翻牌/钟/敲门/幕起/散场是合成 cue；纸纹墨晕用 CSS `feTurbulence` 与主题变量。剧本 `theme` 开局自动切「夜墨/宣纸/靛青」，退出恢复用户选色。

**Bot 正好接上**：凑不齐人时隐士补位演配角，按 `botLines` 在讨论阶段抛一两句，也会投票与推幕。

## 棋馆目录（默认开启、随棋馆）

不新增账号、不新增玩家天梯。排名的主体从「玩家」换成「棋馆」——每个房主棋馆就是一个**棋馆**：

- **发现目录**：馆名、地址、在线人数、剧本数、版本号、是否公开。APK 首启不用手抄 IP，点一下就填好
- **棋馆榜**：按近 7 天场次 / 剧本数排，纯展示
- 每台棋馆本地 `data/` 生成一张**馆帖**（馆名、地址、指纹、剧本数、场次、时间戳），改剧本就重发一版
- 客户端拉一份几十 KB 的聚合 JSON，**本地缓存、离线可用**；目录挂了游戏照常玩，只是不更新
- 写入一律走房主棋馆，**APK 不直连写**；能随时「手动添加棋馆」绕过目录
- 不上报个人战绩，馆自报的量只影响「看起来热不热闹」，不需要防作弊机制

**能挂哪**：默认给一个公开只读公告板地址（`leaderboard/README.md` 里有 Gist / Nostr relay / Cloud Run / CloudBase 三种做法与国内线路注意事项）；换平台只改「04 设置 → 目录地址」一行。可选的 .NET 8 聚合小服务源码在 `leaderboard/BoardServer/`，谁想当榜主谁起，没人起就全离线。

## 本地账号与加密存档

**账号是「每台房主棋馆本地」的，不是中央账号。** 不联网校验、不绑定手机、不收邮箱。题名只在这台棋馆的 `data/` 里留一条记录。

### 怎么用

「04 设置 → 本机账号」：

- **注册**：填名字 + 密码 → **自动创建一份加密存档**（`data/saves/<id>.bin`）
- **登录**：输密码取回存档；断线重连自动续上，不用每局都输
- **每局结束自动更新**：场数、胜场、连续胜、按玩法分场、玩过的剧本，全部写回加密存档
- **导出存档**：再输一次密码核验 → 得到 `.yijusave` 文本（可复制/下载）
- **导入存档**：选文件（或粘贴文本）+ 输当时的密码 → 密码错、包被改过都会**明确拒绝**；核验通过就在当前棋馆建账号并落地，之后继续自动更新

### 两层加密，各管一件事

| 层 | 密钥 | 解决什么 |
| --- | --- | --- |
| 本机保险箱 | `data/vault.key`（32 字节随机，只在这台棋馆） | 存档落盘 AES-256-CBC + HMAC 密文；棋馆随时能读写，**每局自动更新不依赖玩家输密码、重启也不丢** |
| 密码封装 | 玩家密码 PBKDF2-HMAC-SHA256 10 万次 + 随机 salt | 导出包再包一层，带完整性校验；**导入必须核验密码**，跨棋馆迁移靠这一层 |

`data/accounts.json` 只存名字、随机 salt、PBKDF2 校验值和存档文件名，**不存明文密码、不存战绩明文**。密码只在 WebSocket 上传一次，棋馆用完即弃。

**如实边界**：局域网是 `ws://`，密码与聊天在同一条明文链路上；棋馆不落明文已消除「数据库泄露」风险，但**若把棋馆暴露到公网，请自行反代 TLS**。密钥 `vault.key` 丢了，本机存档就解不开（导出包还能靠密码救回来）——请房主备份 `data/`。

### 排名仍是三层

| 层 | 存哪 | 说明 |
| --- | --- | --- |
| 账号存档（主） | 房主棋馆 `data/saves/`（密文） | 登录后每局自动累计，可导出迁移 |
| 本机榜 | `data/leaderboard.json` | 游客按匿名设备指纹累计，重启不丢 |
| 房间 / 本局榜 | 棋馆内存 | 即时、随房间走 |
| 棋馆榜 | 目录聚合 | 馆帖自报场次，纯展示，不产生玩家天梯 |

换一台房主的棋馆 = 新身份，跨服靠「导出 + 密码导入」迁移，不自动认（无中央服务的物理限制）。**没有实时全局玩家天梯**，也不需要——它本来就要一个常驻中央裁判，与「只做玩家游玩用」冲突。

## 发布形态与覆盖升级

**Release 上传 `yiju.apk` + `yiju-release.zip` 两个资产**（服务端包供 .NET 8 机器跑 `./start.sh` 实测）。APK 必须能**直接覆盖升级**，不允许要求玩家卸载重装：

1. 签名固定 `android/keystore/yiju.jks`（alias `yiju`），`debug`/`release` 都指向它，任何版本不换不删
2. `applicationId` 固定 `app.yiju.archive`，Manifest 不写死版本号
3. 版本只从 `android/version.json` 读：首发 `versionCode=1`，**每次发版 +1**、`versionName` 同步递增

验证：`adb install -r yiju.apk`（或手机直接点 APK 覆盖）。构建脚本会打印 `覆盖升级配置` 与 APK 签名 `SHA256:` 指纹，逐版比对必须一致。覆盖安装不清客户端偏好与匿名 token；账号与存档在棋馆 `data/`，更不受影响。
密钥随仓库公开分发，只保证「签名一致」，**不上商店、不证明身份**；要上架请用环境变量指定私有 keystore。详见 `android/keystore/README.md` 与 `RELEASE_LIST.md`。

 `yiju-source.zip` 仅本地留档 / 随仓库分发；`yiju-release.zip` 随 Release 一起发，供房主起馆：里面带棋馆、`scripts/` 示例剧本、`leaderboard/` 目录适配器与非商用协议，自己 `dotnet run` 起馆。剧本更新不发版，往 `scripts/` 丢 JSON 即可。

发布提示词见 `PUBLISH_AGENT.md` 与 `AGENT_PROMPT.md` v5：本地 git + 凭证已在机器里，agent 只做构建、提交、推送、建 Release，零接触凭证，报错即停；品牌已定「弈局 / yiju / 用户原图逐格还原的像素图标：米白底 + 纯黑墨「弈」字 + 朱砂点，无边框无印章」，生成物哈希记在 `android/branding.sha256`，默认一个字不改。

## 已知边界（如实说明）

- 沙盒交付环境没有 .NET 8 SDK 与 Android SDK：规则层、房间/同步层、剧本导演是用 C# 编译器**实编译实跑**的；`Program.cs` 宿主层与 `android/` 工程只做了静态检查，**本机没启动过 WebSocket 服务、没实构建出 APK**。两条构建脚本会在你的环境把这两部分真正编译并产出 4 个文件。
- 房间与战绩存于棋馆内存 + `data/` 本地文件，进程重启时内存房间清空；本机榜、馆档案、**账号与加密存档**保留。`vault.key` 丢失则本机存档不可解（导出包仍可凭密码导入到别处）。
- 隐士为房间内席位，不占连接、不计战绩；真人掉线仍由读秒托管接管。
- 棋馆目录自报场次可灌水，只影响「棋馆看起来热不热闹」，不产生玩家天梯。
- 账号是房主棋馆本地的：换棋馆不自动认，靠导出 + 密码导入迁移；密码走局域网 `ws://` 明文（棋馆不落明文），公网部署请反代 TLS。
- 覆盖升级密钥是公开自分发用的，只保证签名一致，不用于商店上架，也不防「别人签出同名包」。
- 剧本的「真相」由 JSON 的 `endings` 决定，棋馆不做推理；私本按座位投影，不依赖客户端自觉。
- 你画我猜的笔迹是坐标数组，无压感/笔锋；追求画质感可后续加平滑，但不增依赖。
- 将棋 / 麻将 / 桥牌目前是完整可玩的版本，更多番种与高级判和规则还可以继续补。

## 附 · 本版补录

### 一、本机数据加密（加强）

- 口令派生由 PBKDF2-HMAC-SHA256 **10 万轮提至 24 万轮**；旧账号在账号表里记有 `iter`，登录与携谱按各自轮数验算，**旧存档照常读**，新账号与新导出包一律用新轮数。
- 存档升级为 **V2 封装**（`YJW2` / 导出 `YJX2`）：每账号用本机匣钥派生独立子密钥，账号 id 作为附加认证数据写入认证头；改密文、换账号名、把甲的存档改名成乙，都会被 HMAC 拒掉。V1 包仍可读，读后自动写成 V2。
- 明文缓冲用完清零；匣钥、账号表、存档一律**临时文件 + 原子替换**写入，避免写一半留下残卷；支持的系统上把 `vault.key` 与账号表权限收到 `600`。
- 账号表另附 `accounts.mac` 完整性封印，被手改过会拒绝加载并报出告警；老目录没有封印时按旧格式兼容。
- 修掉一个真隐患：旧版读盘没做 Base64 解码，进程内靠缓存能跑，**重启后存档会读不出来**。现改为「解码 → V2 优先 → V1 回落」，并补了重启后读档的专项验证。

### 二、设置项（与主流对齐，全部真接线）

「肆 · 案牍」现分八组共五十余项：画面（画质档 / 清晰倍率 / 字大 / 疏密 / 高对比 / 色觉辅助）、动效（总开关 / 浓淡 / 幕间 / 终局 / 落痕 / 触感 / 随系统减动效）、声音（总开关 + 主音量 / 落子 / 氛围 / 界面四路）、对局习惯（自动整襟 / 双击出牌 / 投子与乞复二次确认 / 着手提示 / 可落点 / 对手余牌 / 自动留谱 / 隐士棋力与更漏超时默认值 / 观席闲谈）、网络与离线（自动重连与间隔 / 仅 WiFi 取外部服务 / 名录·校时·榜单逐项开关 / 本机棋馆地址）、隐私（自动离席 / 后台锁卷 / 清缓存 / 清本机榜 / 换口令 / 删账号）、易用（大点按区 / 长按确认 / 单手 / 不暗屏 / 减少闪烁 / 读屏补充）、关于（声明 / 许可 / 本机诊断）。

## 附 · 寻局与一键启动（终版追加）

### 一、自定义房间：隐士随本席最高段位

在册 6 局房规都多了一项「**隐士随本席最高段位**」。勾上后，开枰瞬间由棋馆读取席中**已题名者的本局最高段位**（当前墨分、上季归档与承袭底分取高），按七阶 → 十阶映射 `0/1/3/5/6/8/9` 自动设定隐士棋力；房规里手选的「隐士棋力」变成开枰前的初值。无人题名则保持房规原值，不擅自改。段位读的是棋馆加密存档，本页改不动。

寻局补位、一键请隐士补满同样按池内 / 席内最高段位；神的领域房间固定第 9 阶，不受此项影响。

### 二、寻局匹配（分池 · 放宽 · 平衡 · 进度）

- **隐藏棋力分**：已题名按本局段位墨分算，未题名按本机胜率给定级分；分数不公开。
- **同段优先**：入池先只找同段且棋力差 ≤80 的人；候 6 秒放宽至 ±1 段（≤200），14 秒 ±2 段（≤400），24 秒全段位但仍优先最接近。
- **接近优先 + 蛇形岔席**：同池里取与最久候者最接近的一桌；四人以上按棋力蛇形交错分座，让两边均值接近。
- **耐心可配**：「案牍 · 设置 → 寻局耐心」20 / 30 / 45 / 60 秒；候满仍不齐，按池内最高段位请隐士补位直接开枰（默认 30 秒，不再是原来 8 秒）。
- **进度与止寻**：底部进度条实时显示已候秒数、当前池范围、池中人数、补位倒计时；「止寻」随时出队，断线自动出队，重复入队会被去重。
- 成局帧带上所用池，玩家看得见「同段 → 放宽」全过程；`matchState` 帧不含任何隐藏分与段位字段。

### 三、服务器可用性验证

沙箱缺 .NET 8 SDK / Runtime，无法实起 ASP.NET 宿主；但 `server/Startup.cs` 是纯 BCL 的同源启动模块，`ServerBootSmoke` 用 Mono 实编译实跑并**真起 TCP 监听**，验证了 `/api/health`、`/api/info`、`/api/startup`、`/rules/manifest.json`、未知路由 404 与 `/ws` 的 RFC 6455 `101` 升级握手（标准向量 `Sec-WebSocket-Accept`），共 37 项全过。启动项、配置优先级、布局自检、可照抄地址也在同一组里真跑。agent 环境用 `./start.sh` 实起完整宿主。
